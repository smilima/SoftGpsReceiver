How this receiver works

The receiver post-processes a file of raw IF samples in four stages. Every intermediate quantity is kept so it can be inspected on the other tabs. Press F5 (Run all) or run the stages one at a time (F6 to F9).

0. Input signal

The file contains real (or I/Q) samples of the front-end output. The sampling frequency fs and the intermediate frequency fIF are read from the file name (for example fs38_192-if9_55 means 38.192 MHz and 9.55 MHz). For this kind of recording one C/A code period (1 ms) is N = fs/1000 = 38192 samples, or about 37.3 samples per chip. The GPS signal is about 20 dB below the thermal noise, so the Raw signal tab shows only the front-end filter shape and the ADC level usage. A Gaussian-like histogram that fills the quantiser without clipping is ideal.

1. C/A code

Each satellite transmits a 1023-chip Gold code at 1.023 Mchip/s, generated by two 10-stage shift registers:

G1 = 1 + x3 + x10,   G2 = 1 + x2 + x3 + x6 + x8 + x9 + x10,   C/A = G1 ⊕ G2i

G2i is the XOR of two G2 stages selected per PRN (IS-GPS-200 Table 3-Ia). This is equivalent to delaying G2. The autocorrelation takes only the values 1023, −1, −65 and +63. That low sidelobe and cross-correlation level is what lets all satellites share one frequency (CDMA).

2. Acquisition (parallel code-phase search)

For every Doppler bin fd (default ±10 kHz in 500 Hz steps) the incoming 1-ms block is mixed to baseband and circularly correlated with the sampled code of every PRN using FFTs:

R(τ, fd) = IFFT{ FFT[x(n) e−j2π(fIF+fd)n/fs] · conj(FFT[c(n)]) }

|R|2 is summed non-coherently over several 1-ms blocks. Because 38192 is not a power of two, the FFT uses Bluestein's chirp-z algorithm. The detection metric is the ratio of the highest peak to the highest peak more than one chip away; a satellite is declared present when it exceeds the threshold (2.5). C/N0 is estimated from (peak − noise)/noise = (C/N0)·T.

Fine frequency: the code is wiped off, 0.5-ms coherent sums Pk are formed, and the spectrum of Pk2 is evaluated on a 1 Hz grid. Squaring removes the ±1 navigation data, so bit transitions do not split the peak. The peak sits at twice the residual frequency.

3. Tracking

Each channel runs, every code period (T ≈ 1 ms):

  • a carrier NCO (32-bit phase accumulator, 1024-entry sine table) and a code NCO;
  • early, prompt and late correlators at ±0.5 chip: I + jQ = Σ x(n) e−jφ(n) c(θ(n) + δ)
  • a Costas PLL discriminator eφ = atan(QP/IP), which is insensitive to the 180° data flips;
  • an FLL assist during pull-in, ef = atan(cross/dot)/(2πT), where cross = I1Q2 − I2Q1 and dot = I1I2 + Q1Q2;
  • a 2nd-order loop filter (Kaplan): ωn = 8ζBn/(4ζ2+1);  v += T(ωn2eφ + ω0fef);  fNCO = f0 + (v + 2ζωneφ)/2π
  • a DLL with the normalised early-minus-late envelope discriminator eτ = (1−d)(|E|−|L|)/(|E|+|L|) chips and a 2nd-order loop filter;
  • C/N0 from the M2M4 moment estimator, Ps = √(2M22 − M4), and a phase lock indicator cos 2Δφ = (I2−Q2)/(I2+Q2).

For every millisecond the receiver stores the NCO states, the six correlator outputs, all discriminators, and the sample index of each code epoch, which is the basis of the pseudorange. The Correlator shape tab recomputes a bank of correlators from the stored NCO state to show the actual correlation triangle, rounded by the front-end filter.

4. Bit synchronisation and navigation message

Data bits last 20 code periods. A histogram of prompt sign changes modulo 20 ms identifies the bit edge, and each bit is the sum of 20 prompt values. Subframes (300 bits, 6 s) begin with the preamble 10001011. A candidate is accepted only if the TLM and HOW words pass the parity check of IS-GPS-200 Table 20-XIV:

di = Di ⊕ D30*;   D25 = D29* ⊕ d1 ⊕ d2 ⊕ d3 ⊕ d5 ⊕ d6 ⊕ d10 ⊕ …

An inverted preamble reveals the 180° PLL ambiguity. The HOW gives the TOW count (time of the next subframe) and the subframe ID:

SubframeContent
1week number, L2 codes, URA, 6-bit SV health, IODC, TGD, clock polynomial toc, af0, af1, af2
2, 3Keplerian ephemeris with harmonic corrections (IODE, √A, e, M0, Δn, ω, Ω0, Ω̇, i0, IDOT, Cuc … Cis, toe)
4, 525 pages each: almanac, health summaries (page 25), iono/UTC (SF4 p18), special message (p17), NMCT (p13)

Timing: once a subframe start (tracking millisecond m0) and its TOW are known, the satellite transmit time of every code epoch is ttx(m) = TOWstart + (m − m0)·1 ms. This is exact because each C/A period is exactly 1 ms of satellite time.

5. Satellite position and clock (IS-GPS-200 Table 20-IV)

A = (√A)2, n = √(μ/A3) + Δn, M = M0 + n tk, E = M + e sin E (iterated), ν = atan2(√(1−e2) sin E, cos E − e), Φ = ν + ω … Δtsv = af0 + af1(t−toc) + af2(t−toc)2 + F e √A sin E − TGD

The Satellites tab lists every intermediate value of this computation for any satellite and epoch.

6. Pseudoranges and position

At each measurement epoch (a common receiver sample index R) the transmit time of every channel is interpolated from the code-epoch timing. The receiver clock is the sample counter, trx(R) = t0 + R/fs, so the solved clock bias drifts at the sampling-clock frequency error.

ρ = c (trx − ttx);   ρc = ρ + cΔtsv − I − T;   ρc = |R3(ωeτ) rsat − r| + b

The linearised system δρ = H δx (rows = [−uT, 1]) is solved by iterative least squares from the Earth's centre. The Least-squares detail tab shows every iteration, the design matrix and the cofactor matrix Q = (HTH)−1, rotated to East/North/Up, from which the DOP values follow:

GDOP = √tr Q, PDOP = √(QEE+QNN+QUU), HDOP = √(QEE+QNN), VDOP = √QUU, TDOP = √Qbb

Corrections: satellite clock (including the relativistic term and TGD), Earth rotation during signal flight (Sagnac), Saastamoinen troposphere, and the Klobuchar ionosphere if page 18 of subframe 4 was received.

Velocity comes from the carrier Doppler: ρ̇ = −λ fD = (vsat − v)·u + d. The sign of the IF Doppler, which flips with high-side LO injection, is detected automatically from the velocity residuals. The common term d contains both the receiver clock drift and any error in the nominal IF. The effective IF reported on the Position tab is therefore a check of the front-end frequency plan.

7. Galileo E1 Open Service

Galileo E1 shares the L1 carrier frequency with GPS, so one recording holds both systems. The same four stages process it, with these differences:

GPS L1 C/AGalileo E1-B/C
Code1023-chip Gold code, 1 ms4092-chip memory code from a table, 4 ms
ModulationBPSK(1)BOC(1,1) (CBOC, see below): two lobes at +/-1.023 MHz
Componentsone, with dataE1-B with data, E1-C pilot with a 25-chip secondary code
Data rate50 bit/s, parity250 symbols/s, rate 1/2 FEC, interleaved, CRC-24Q
Time scaleGPS timeGalileo System Time (nominally the same weeks and seconds)

Signal

Each chip is split by a square sub-carrier into +c, -c. This gives the correlation function a peak about one third as wide as the C/A triangle, with negative side lobes at +/-0.5 chip: open the Correlator shape tab on a Galileo channel to see them. The transmitted CBOC signal adds a little BOC(6,1) power; the receiver correlates against plain BOC(1,1), which loses about 0.4 dB.

Acquisition

A 4 ms replica is correlated against an 8 ms window, so the window always contains one whole code period and a sign change cannot cancel the peak. The Doppler search shifts one spectrum instead of mixing again, and only the band around the carrier is kept. E1-B and E1-C are searched separately. They are unrelated codes on the same signal, so a satellite is declared present only when both peak at the same delay and Doppler, which noise cannot arrange. With GPS satellites in view, the search is centred on their mean Doppler, which removes the receiver clock offset.

Fine frequency uses squared 2 ms pilot correlations, which are insensitive to the sign changes at 4 ms boundaries and unambiguous to +/-125 Hz. That range matters: a Costas loop with T = 4 ms also locks 125 Hz away from the carrier, 3.9 dB down, and then the data cannot be decoded.

Tracking

Every 4 ms the pilot drives the Costas PLL and the DLL through early, prompt and late correlators, and a fourth correlator takes the E1-B prompt for the data symbols. The early/late spacing is 0.15 chip with the discriminator gain (1 - 3d) / 3, because the peak falls as 1 - 3|t|. Code Doppler reaches about 2 chips/s, more than a narrow DLL can follow on such a narrow peak, so the code NCO is always aided by the carrier from the first epoch. C/N0 is measured on the pilot and reported for the whole signal, 3 dB higher.

I/NAV message

The symbol rate equals the code rate, so there is no bit synchronisation. Pages are found by the 10-symbol pattern 0101100000 that starts each 1 s page part. The pattern also occurs by chance, and dummy pages repeat such a match at a fixed place every page, so the offset is chosen by which candidate gives pages that pass the CRC. Each of the 240 remaining symbols is deinterleaved (30 columns by 8 rows) and Viterbi-decoded (constraint length 7, polynomials 171 and 133 octal, the second inverted). An even and an odd part give a 128-bit word protected by CRC-24Q. Words 1 to 4 hold the ephemeris and clock, and word 5 the group delay, health and time.

The TOW in words 5, 6 and 0 is the time of the first chip of the page. A satellite with nothing valid to send broadcasts dummy words of type 63, which decode cleanly but carry no ephemeris.

Position

The orbit is computed as for GPS, with mu = 3.986004418e14 m^3/s^2. The clock correction subtracts BGD(E1,E5b) in place of TGD. When both systems are used, a fifth unknown absorbs the bias between them: the GPS to Galileo time offset plus the different receiver delays of the two signals. It costs one satellite, so a combined fix needs five. A Galileo-only fix needs four.

In any mode a measurement is used only if a decoded word that passed its check lies close to it in time (within 4 s for I/NAV words, 10 s for complete GPS subframes). This keeps a channel that has lost lock out of the solution, which the C/N0 estimate cannot do reliably.

Limitations

  • Only E1 is processed. Galileo E5 and E6, and OSNMA authentication, are not.
  • The NeQuick ionosphere model is not implemented. GPS Klobuchar parameters are applied to Galileo when they are in the recording, so a Galileo-only fix has no ionospheric correction.
  • The pilot is tracked with a Costas loop and the secondary code is not used. After a deep fade a weak satellite can therefore lock 125 Hz away and stop decoding, although a loop using the secondary code could hold it.
  • Code aiding needs the sign of the IF Doppler before it can be detected, so a recording with an inverted spectrum needs the IF Doppler sign set by hand in the settings.
  • Galileo almanac words are recognised but not decoded.
